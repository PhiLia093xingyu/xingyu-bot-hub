# 01 架构说明

## 组件与端口

| 组件 | 路径（建议） | 端口 | 作用 |
|---|---|---|---|
| 微信 4.1.10.27 | `C:\Program Files\Tencent\Weixin` | — | 客户端本体 |
| `version.dll` | 同上 | `30001` | hook，代理加载；提供 HTTP API 与消息回调 |

## 数据流

### 收消息
1. 微信收到消息 → hook 在 `SyncBatch` 的 `AddMsg` 向量处捕获；
2. hook 以 JSON POST 到 `http://127.0.0.1:30002/event`；
3. 桥把 JSON 转成 OneBot 事件（`message_type=private/group`）；
4. 桥通过反向 WS 推到 AstrBot 的 `wechat` 平台（`ws://127.0.0.1:24875/ws`）；
5. AstrBot 跑插件/LLM，调用 `send_*` action 回到桥；
6. 桥调用 hook 的 `/SendTextMsg`、`/SendImgMsg` 发到微信。

### 发消息
- 文本：`POST http://127.0.0.1:30001/SendTextMsg`，参数 `{"wxidorgid": "...", "msg": "..."}`；
- 图片：`POST /SendImgMsg`，参数 `{"wxidorgid": "...", "path": "本地图片路径"}`；
- 群聊时 `wxidorgid` 传 `xxx@chatroom`，私聊传对方 wxid。

## 关键启动参数

微信必须带以下参数启动，否则 hook 不会安装消息回调：

```
Weixin.exe StartPort=30001 RecvType=2 CallBackURL="http://127.0.0.1:30002/event"
```

- `StartPort`：hook HTTP 端口；
- `RecvType=2`：启用 protobuf 消息解析/回调；
- `CallBackURL`：消息回调地址。

## 与 QQ 的关系

QQ 侧与微信侧**互相独立**：
- 微信桥只需要 AstrBot；
- QQ 需要 NapCat Desktop（UI）+ SnowLuma（OneBot 后端）+ QQ NT 客户端；
- AstrBot 里两个平台可以共存（`wechat` 与 `ncd-app...`），本包不包含 QQ 客户端（体积过大），只给配置模板。

## 能力边界

| 能力 | 微信（本包） |
|---|---|
| 文本收发 | ✅ |
| 图片收发 | ✅（收图自动定位缓存 `.dat` 并解密） |
| 收藏表情包识别 | ✅（CDN 下载 → 首帧 PNG → 视觉模型） |
| 群聊 @ 识别 | ✅（转 OneBot `at` 段） |
| 语音接收 → 文字 | ✅（内存扫 SILK → pilk 解码 → whisper） |
| 语音发送 | ❌ 需 C++ 逆向（SILK 编码 + CDN 上传 + 语音消息构造） |
| 拍一拍 | ❌ 入口在微信内部系统消息链路，未定位 |
| 文件/视频发送 | ❌ hook 无接口 |
